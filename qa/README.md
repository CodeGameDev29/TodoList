# QA harness

This stdlib-only harness records acceptance and independent judgments for the implemented TodoList application. Core acceptance is in `acceptance.md`, optional feature acceptance in `optional-enhancements.md`, and repository review acceptance in `code-review-acceptance.md`. Browser journey definitions live in `journeys/`. Acceptance documents, journeys, schemas, class registry, and ledger are committed. Actual screenshots, traces, console, network, titles, and timing go to `.qa-artifacts/` (or `TODOLIST_QA_ARTIFACTS`) and are never committed.

Use `python qa/harness.py preflight` to validate all recursive acceptance and journey definitions, then `new-report <id>` to create an unjudged report skeleton. `validate` checks reports and journeys; `judge-pack <id>` freezes only a complete, independently judgeable report; `add-class <json>` or `intake <id>` registers a valid proposed class; `record <id>` updates the per-class ledger; and `status` prints it.

Every runtime report records a foreground headed browser title and wall clock, exact step evidence, runner and different judge identities, PASS/FAIL rows, and a change ID. Evidence paths must exist inside the configured artifact root; trace, console, and network capture may explicitly be `captured-empty`. Invalid, incomplete, unjudged, or instrument-error runs are never recorded. A class closes only after all regression rows are green and two clean judged rounds; a later hit reopens it. Two consecutive hits on the same shipped change mark that class as a process failure.

Report IDs contain ASCII letters, digits, underscores, and hyphens, starting with a letter or digit; Windows device names are reserved. Resolved report and judge-pack paths must stay inside their artifact directories. Completed reports require timezone-aware timestamps in chronological order and finite, nonnegative numeric `wall_clock_ms`. Each report ID can be recorded only once, including reports with no class rows. The ledger's optional `recorded_report_ids` list tracks new recordings; historical class event IDs also prevent replay.

Before handoff, run `npm run format:check` and obtain an independent `code-reviewer` assessment against [the researched rubric](../.claude/project/CODE-REVIEW-RUBRIC.md). Each applicable rule needs a verdict and evidence. Formatter results complement the review; they do not prove correctness. See the root README for tool installation and validation commands.
